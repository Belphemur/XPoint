# Changelog

All notable changes to XPoint are documented in this file.

## [Unreleased]

### Added

- Async input sampling (design `docs/design/2026-09-20-async-input.md`): on PSRAM boards a 10 ms input task samples the button ladder continuously, so presses landing inside any busy window (e-ink refresh, multi-second page builds, renders — the soak measured a 25.8 s window) are latched and delivered on the next UI frame instead of dropped. `InputManager::update()` becomes a drain path on the app task (per-frame latch via `beginInputFrame()`), while the poll task owns sampling, debouncing, and the hold machinery; press AND release edges are queued (the reader grammar is release-driven). The app's entire input semantics (release turns, holds, auto-repeat, home-key gestures) are unchanged. PSRAM-only (~6.5 KB DRAM); C3/Classic keep polled input.

- One-page-ahead prerender (P4 of `docs/design/2026-09-19-freetype-render-cache.md`, port of upstream 60079923 adapted to the TTF engine): after a fully committed page frame, page N+1's content is painted into the framebuffer (no status bar, no flush) so a forward page turn skips layout, build, and the base paint — only the status bar and the display commit run. One RenderLock transaction started after the previous refresh completes; invalidated on any other render pass and refused while overlays, deferred overlay pushes, chrome popups, or chapter builds are live, so the panel can never show the next page bare.
- Text rendering mode setting (task6): the "Text Anti-Aliasing" row becomes "Text Rendering" with two modes — **Crisp** (default; hinted 1-bit mono glyphs straight from FreeType, no coverage quantization or dual-plane walk) and **Smooth** (opt-in; 8-bit AA coverage + dual-plane gray, relying on the P1 glyph cache). The old `textAntiAliasing` bool is fully replaced (no settings JSON migration; absent keys default to Crisp). Mode switches flush the FT faces' glyph caches via `setRenderOptions()` and fold into the FIBP fingerprint tag; Light hinting stays on in both modes with the stack-probe auto-degrade guard.

- SD-cached per-face font fingerprint (P3.1 of `docs/design/2026-09-19-freetype-render-cache.md`): `BookFontLoader` persists each face's chained FNV-1a hash as a fixed 28-byte record under `/.crosspoint/fonts/` (`fp_<pathhash>.bin`), valid only when {fileSize, mtime, first-4 KB head hash, incoming chain seed} all match — so family opens stop FNV-walking up to 4 × 2 MB of resident font bytes. Records are served only with a real SD mtime (mtime 0 bypasses the cache, fail closed), corrupt records recompute and rewrite, and `scanFonts` now populates the previously-never-set `FontFaceInfo::mtime` from `HalFile::modificationTime()`. Fingerprint semantics unchanged (content-based, computed before the fallback tail, mirror-safe with the prefetch worker).
- Background FIBP chapter-index prefetch ("index-ahead", design addendum §7 of `docs/design/2026-09-18-freetype-backend-as-built.md`): on S3-class builds (PSRAM + FreeType) a 24KB-stack, priority-1 worker task pinned to core 0 lays out spine chapters ahead of the reader and commits their FIBP caches to SD, so chapter entry hits the cache instead of the blocking "Indexing" popup. The worker owns its own `TtfBookRuntime` and `FtFont` faces (FT face create/destroy stays on the main thread), replicates the loader fingerprint byte-for-byte so its caches land under the reader's generation names, skips spines whose cache exists, defers to the reader's sync rebuild via a single-writer handoff, and re-seeds on generation bumps. Inert on C3 / stb builds (synchronous fallback unchanged); the build driver is shared with the reader via the new `ChapterIndexEngine`.
- FreeType-backed native-TTF reader (design `docs/design/2026-09-17-freetype-font-backend.md`, #146): under `CROSSPOINT_FONT_BACKEND_FT=1` on PSRAM-class devices (x4pro/x4c/papermono), `BookFontLoader` builds the reading font chain over the SDK's `FtFont` instead of stb-backed `TtfFont` — true bold/italic from variable-font `wght`/`ital`/`slnt` axes with FT-side oblique/embolden synthesis, per-face glyph arena eliminated (FreeType owns the glyph slot, all FT heap PSRAM-preferring), and metrics-only `glyphBounds` band-culling parity. Requires freeink-sdk ≥ `6a8addc` (#26: `FtFont::glyphBounds`, CFF/OTTO module enablement, rasterize bitmap-lifetime fix). Stb path remains compilable for rollback (`CROSSPOINT_FONT_BACKEND_FT=0`).

### Changed

- freeink-sdk submodule bump (P1 glyph cache + hinting re-enable, `docs/design/2026-09-19-freetype-render-cache.md`): `FtFont` gains a bounded LRU glyph bitmap cache (512 KB/face default, 2 MB cap, flushed by `setRenderOptions`/re-init/shrink) so hinted rendering costs one FT render per glyph instead of per page — and reader render options move to **Light hinting** (auto-hinter compiled in; per-face runtime stack probe degrades to unhinted when the Adobe-interpreter depth would not fit the 24 KB prefetch worker). The effective per-face modes (hinting + raster mode) are folded into the font fingerprint in both parity sites (loader + prefetch worker), so FIBP caches regenerate on any mode change.
- Older SDK work (`2dbd5a8 → 43fed43`, upstream FtFont #111/#112): render options via `setRenderOptions`, layout revision 12→13 (GSUB ligatures), host font-backend test variants link the SDK's `Gsub.cpp`.

### Fixed

- Device-soak fixes for the index-ahead prefetch (PR #153 follow-up, 2026-09-19): background builds now keep the CPU at full speed via `preventAutoSleep()` and a 2 s normal-power dwell hysteresis in the governor — the input-idle governor previously dropped to low-power mid-index (measured: 2.6 s/page spine builds, per-second frequency flip-flops during render-polled builds, and a task-watchdog IDLE0 starvation reboot on a 177-spine book). The prefetch worker stack was raised 24→32 KB (device-measured HWM 1792 B on a 93-page image-heavy spine) and the progress-flush worker 4→6 KB (HWM 1400 B). The reader's in-book cache-clear now stops the worker and closes the TTF runtime before removing the cache folder so the FIBP `ficache/` subtree is actually deleted (open handles made the recursive removal fail), with an explicit fallback removal in `clearBookCache()`. Render stack/heap telemetry moved behind the book render path and the render-polled worker-delegation wait throttled to 250 ms. A delegated build that exceeds a 1.5 s grace is taken over by the reader (worker aborts at the next page boundary, the reader resumes its partial and builds only to the target page) so a chapter entry can no longer park the user on the Indexing popup for the whole spine build. The prefetch plan is capped to the next chapter only (`fibp::kPrefetchLookaheadSpines = 1`, plan and change-detection share one notified-spine snapshot) and is now fired by a PROGRESS trigger — `fibp::shouldPrefetchNext(page, pageCount)` enqueues the next chapter once the reader is inside the last ~10% of the current chapter (ceil-rounded; `pageCount == 0` never triggers) — instead of unconditionally at chapter entry, so chapters that may never be read are no longer built. Whole-book prefetching caused the SD-write pressure and the worker task-watchdog crash on a 177-spine book.
- SD-card firmware update and other confirmation dialogs: pressing Confirm was treated as Cancel after the defensive pop-result guard introduced in #75. Confirm again starts the update (this also unblocks locked X4 Pro devices downgrading to upstream CrossPoint firmware from the SD card).
